# Verification and limits

## Inherited baseline

0.6.0 preserves the 0.5.2 runtime JavaScript. The baseline passed 198 automated checks/groups: core 78, Client/controller 72, Native production integration 26, Native lifecycle 8, Native boundary 3, package 10 and relocated shared-runtime resolution 1. That run used 75 scripted model requests and zero external-model requests. Counts are checks/groups, not a claim of exhaustive state-space coverage.

The repository ports these checks to relative paths and replaces comparisons against historical development folders with pinned source hashes. The fresh V0.6 portable suite passed **198/198** on the declared Windows Desktop runtime. Generated outputs may contain synthetic request bodies and machine paths; they stay ignored. Run the repository suite to reproduce the result; a future modification is not covered by this recorded pass.

## Real-model practical acceptance

Four subsequent scenarios exercised six targets: independent contract conflict discovery/agreement/continuation; parallel useful contributions; review/revision/validation; a parent-responsible native helper; respected sandbox denial with same-worker approved fallback; and retirement/reopening/restart followed by fresh confirmed work. No blocking coordination defect was established. Waiting reassessment was observed: a decision could leave an unsatisfied payload wait intact, then an actual handoff enabled progress.

Reports distinguish manager-observed receipts/records from worker-reported filesystem/tests. Coding-agent review did not independently rerun every artifact. No complete native-call count or exact-concurrency proof is claimed.

The four parent-session billing exports totalled **USD 3.2026962** at their exported meter rates, including detailed retrospective reporting. They excluded helper/subagent cost and are not a provider invoice or an estimate of the plugin's incremental overhead. Four report-writing requests directly accounted for USD 0.3743128. Raw exports, Session IDs, personal paths and trajectories are intentionally not published.

## Release verification

The release script builds an allowlisted npm-compatible archive with deterministic headers, checksums and no lifecycle hooks. Runtime assets match their pinned tested baseline and private/generated files are excluded. A real pnpm offline install downloaded zero packages, materialized the archive, and passed a separate native shared-peer resolution/owner setup/participant-Tool check with NODE_PATH absent after its original archive-source folder was renamed. This additional gate is **1/1**, separate from the 198-check suite. No installation into the active user profile or real GUI upgrade was performed for V0.6. The original runtime's CRLF/mixed line endings are deliberately preserved by Git attributes to keep tested bytes identical across checkouts.

## Security review

Read-only source review found no embedded credentials, personal absolute paths, external telemetry client or material runtime vulnerability requiring an implementation change. The review identified/documented teammate environment disclosure, full historical team visibility, retained data/backups and unbounded aggregate growth. This is not a penetration test, dependency-advisory database audit or a security guarantee.

## Remaining limits

- Actual user refusal of a native approval dialog and unavailable approval as a distinct cause were not exercised by the sandbox-denial scenario.
- Rare contested/stale-write, manager-reserved hold, pending-work retirement and crash/replay races are not all real-model tested; targeted scripted coverage does not imply exhaustive proof.
- No global absence of replay throughout downtime or exact process-restart instant was established.
- Live registration/source checks do not prove rendered appearance, accessibility or actual approval-dialog behavior.
- Histories/arrays grow and the aggregate is rewritten; this is for trusted small/local teams, not an adversarial multi-tenant or unlimited-scale service. No retention/compaction system is provided.
- Only the declared DSH version and Windows Desktop environment were verified. No independent Linux/macOS or unsupported-version acceptance is claimed.

See [source-only manual testing](https://github.com/Wyakh/dsh-sessions-teamwork/blob/v0.6.0/docs/TESTING.md) in the source repository and [security boundaries](../SECURITY.md). No additional manual test round is required merely to restate these limitations.
